= Offline κρατήσεις και ενιαία διαθεσιμότητα
:revdate: Ιούλιος 2026

Η έκδοση 2.0 ενοποιεί τη διαθεσιμότητα online και φυσικού καταστήματος. Η διαθέσιμη ποσότητα υπολογίζεται ως φυσικά οχήματα μείον ενεργές κρατήσεις, ενεργά `AvailabilityBlock` και τα υφιστάμενα `GroupUnavailability`.

== Offline κράτηση

Ο χρήστης Backoffice δημιουργεί άμεσα επιβεβαιωμένη κράτηση με πηγή, external reference, χρονικό διάστημα, σημεία, VehicleGroup, πελάτη και χειροκίνητο συνολικό ποσό. Η πινακίδα είναι προαιρετική κατά τη δημιουργία αλλά υποχρεωτική πριν την παράδοση. Προτιμώμενο μοντέλο μπορεί να καταγραφεί χωρίς να δεσμεύει φυσικό όχημα.

Η ανάθεση άλλου μοντέλου επιτρέπεται μόνο εντός του ίδιου group ή ως ρητά εγκεκριμένο upgrade. Downgrade και manual overbooking δεν επιτρέπονται.

== Availability blocks

Τα blocks χρησιμοποιούνται για service, βλάβη ή άλλη λειτουργική αδυναμία και μπορούν να αφορούν:

* μία πινακίδα (`VEHICLE_ITEM`, ποσότητα 1),
* ένα μοντέλο (`VEHICLE`),
* ένα group και ποσότητα (`VEHICLE_GROUP`).

Το σύστημα απορρίπτει άκυρα διαστήματα και blocks που συγκρούονται με ενεργή κράτηση συγκεκριμένης πινακίδας. Η ακύρωση διατηρεί το ιστορικό.

== Ασφάλεια και ενεργοποίηση

Το feature toggle `offlineInventoryEnabled` είναι global και default `OFF`. Οι ρόλοι `BASIC` και `Full Access` έχουν πρόσβαση. Search, select, reserve και Backoffice χρησιμοποιούν κοινό availability service. Κατά την αποθήκευση γίνεται νέος έλεγχος μέσα σε transaction με database lock, ώστε δύο αιτήματα να μην καταναλώσουν την ίδια τελευταία διαθεσιμότητα.

== Εκτός τρέχοντος scope

Προσωρινά holds, χρόνος προετοιμασίας, πραγματική κίνηση/location planning, manual overbooking, POS/ERP integration και reports παραμένουν σε επόμενα slices.
